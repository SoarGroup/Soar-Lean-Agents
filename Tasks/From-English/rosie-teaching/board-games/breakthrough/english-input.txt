Breakthrough: English input (Rosie teaching script)

The instructor's statements to Rosie, verbatim and in order (script.txt). "Load <name>" sets up the world state in <name>.world in this folder. A bare "Ok." from the instructor answers Rosie's request to set up a state (the puzzle, a failure condition or the goal), "Done." ends the teaching, and the final "No." declines Rosie's offer to solve the task. Rosie's side of the dialog is in dialog.txt; dialog.html shows the dialog with pictures of the world states.

Teaching script:
  1. The name of the game is break-through.
  2. Load init-breakthrough.   [world state: init-breakthrough.world]
  3. Ok.
  4. If a red block is under a clear location then you can move the block onto the location.
  5. If a location is not below an object then it is clear.
  6. Load second-breakthrough.   [world state: second-breakthrough.world]
  7. If an occupied location is attackable by a red block then you can remove a block on the occupied location and move the red block onto the occupied location.
  8. If a location is below a blue block then it is occupied.
  9. If a location is under an object and the location is diagonal with the object then the object is attackable by the location.
 10. Load final-breakthrough.   [world state: final-breakthrough.world]
 11. The goal is that a red location is below a red block.
 12. Ok.
 13. Load fail-breakthrough.   [world state: fail-breakthrough.world]
 14. If a blue location is occupied then you lose.
 15. Ok.
 16. Done.
 17. No.

World vocabulary (extracted from the world files loaded above; not part of the dialog):
  Object categories: block, location
  Object attributes: color (blue1, red1); column (numeric, 1 to 4); name (garbage); row (numeric, 1 to 4)
  Relations: above1, below1, diagonal-with1, on1, under1
  Names are as written in the world files, including their trailing 1 (red1, on1).

Source: IJCAI 2019 teaching data for games and puzzles, teaching-data/board-games/breakthrough/.
