Family Crossing: English input (Rosie teaching script)

The instructor's statements to Rosie, verbatim and in order (script.txt). "Load <name>" sets up the world state in <name>.world in this folder. A bare "Ok." from the instructor answers Rosie's request to set up a state (the puzzle, a failure condition or the goal), "Done." ends the teaching, and the final "No." declines Rosie's offer to solve the task. Rosie's side of the dialog is in dialog.txt; dialog.html shows the dialog with pictures of the world states.

Teaching script:
  1. The name of the puzzle is family-cross.
  2. Load init-familycross.   [world state: init-familycross.world]
  3. Ok.
  4. You can move a child that is on the current bank and another child that is on the current bank and the boat onto the opposite bank.
  5. If an object is below a boat then it is current.
  6. If a location is not below a boat then it is opposite.
  7. The name of an action is ferry-one.
  8. You can move the boat and a block on the current bank onto the opposite bank.
  9. The solution has nine steps.
 10. Load final-familycross.   [world state: final-familycross.world]
 11. The name of the goal is all-crossed.
 12. Ok.
 13. The goal is that all the blocks are on a destination bank.
 14. Done.
 15. No.

World vocabulary (extracted from the world files loaded above; not part of the dialog):
  Object categories: block, location
  Object attributes: name (destination1); shape (adult1, bank1, boat1, child1)
  Relations: below1, on1
  Names are as written in the world files, including their trailing 1 (red1, on1).

Source: IJCAI 2019 teaching data for games and puzzles, teaching-data/river-crossing-puzzles/family-crossing/.
